# 窗口截图误选整屏覆盖层：测试与交付报告

## 范围与环境

- 日期：2026-10-26，Asia/Shanghai。
- 环境：macOS 26.6.2（25G83）、Xcode 27.1（27A9275）、arm64；双屏，内屏 1710×1107 点 / 2×，外屏 1920×1080 点 / 1×。
- 基线：main / 0991817；测试时本次源码未提交。两份原有 window-capture-isolation 报告的删除保持不变，不纳入本次提交。
- BUG-01：选择窗口截图时，千问办公上方的整屏悬浮窗口抢先命中，表现为只能选择整个显示器。

## 复现、根因与修复

- 实际系统窗口枚举发现：普通千问办公窗口可见；其上方另有录屏层（layer 101）、助手层（layer 3）及系统覆盖层。
- 原实现保留所有非负层级窗口，矩形命中直接取最靠前的窗口，导致整屏覆盖层挡住普通应用。
- 复现探针调用项目实际的 WindowStack、ShareableContentFilter、OverlayInteractionGeometry，修改前输出：

```text
Expected: Qwen window, (-77, 167, 1286, 869)
Actual: 系统覆盖窗口, (-332, 27, 1920, 1080)
FAIL: Window capture selects a full-display overlay over Qwen
```

- 修复：传递 ScreenCaptureKit 的 windowLayer；窗口选择仅提供普通层级（0）的应用窗口，排除悬浮、菜单和录屏等覆盖层，保持普通窗口的 WindowServer 前后顺序。真正全屏的普通应用仍可选择；非普通层级的浮动工具面板不作为目标。
- 未取得前后截图：界面控制工具连接无主窗口的菜单栏 Wnip 超时；修复前保留实测系统枚举与行为测试证据，修复后由用户在新安装版本直接操作验收。
- API 依据：[Apple SCWindow.windowLayer](https://developer.apple.com/documentation/screencapturekit/scwindow/windowlayer)。
