# Wnip 截图入口与全局快捷键设计

## 目标

把现有菜单、快捷键、权限、ScreenCaptureKit 和多显示器浮层连接成可运行的截图启动流程，并在设置页提供真正的快捷键录制能力。

## 用户行为

- 菜单栏“区域截图”启动可拖拽的区域框选。
- 菜单栏“窗口截图”启动窗口悬停高亮与点击选择。
- 菜单栏“全屏截图”启动显示器选择。
- 全局快捷键默认使用 `⇧⌘X`，行为与“区域截图”一致。
- 设置页提供“区域截图快捷键”录制控件。用户点击控件后按下包含 Command、Option、Control 或 Shift 的组合键即可保存。
- 单独修饰键、无修饰键和 `Esc` 不保存；`Esc` 退出录制。
- 新快捷键注册冲突或失败时显示错误，继续保留并使用旧快捷键。
- 截图流程中按 `Esc` 取消并关闭全部浮层。

## 架构

新增主线程隔离的 `CaptureCoordinator`，作为应用入口层的唯一状态所有者。它依赖现有的 `PermissionService`、`ScreenCaptureService`、`OverlayController`、`HotKeyService` 和 `PreferencesStore`，并向 SwiftUI 暴露截图命令、快捷键显示值和可呈现错误。

启动流程如下：

1. 应用启动时加载偏好并注册已保存的全局快捷键。
2. 菜单命令或快捷键调用 `startCapture(mode:)`。
3. 协调器结束旧会话和旧浮层，检查屏幕录制权限。
4. 未授权时请求权限；仍未授权则显示可操作错误，不创建浮层。
5. 授权后异步获取显示器和候选窗口，构造 `OverlayPresentation` 并显示多屏浮层。
6. 浮层回调更新选区；取消时统一清理浮层并结束当前任务。

首轮接线以“能够进入并操作三种选择模式”为完成边界。截图确认后的图像编辑、复制和保存继续沿用后续既定实现，不在本次入口修复中伪造完成状态。

## 设置界面

设置页使用原生 SwiftUI `Form`。快捷键录制控件显示当前组合键；录制期间以强调色边框和提示文字表示等待输入。键盘事件转换为 `HotKeyShortcut` 后交给协调器：先尝试注册，成功才持久化，失败则展示错误且不改变当前值。

## 错误处理

- 权限拒绝：显示说明，并提供打开“屏幕与系统音频录制”设置的按钮。
- 内容枚举失败：关闭浮层并显示底层可读错误。
- 快捷键冲突：保留旧注册与旧偏好，设置页显示冲突提示。
- 新截图请求到达时：取消旧异步任务并关闭旧浮层，避免多个会话重叠。

## 测试与验收

- 协调器测试覆盖菜单/快捷键启动区域模式、窗口模式、全屏模式、权限拒绝、重复启动与取消清理。
- 快捷键更新测试覆盖注册成功后持久化，以及冲突时保留旧值。
- 快捷键事件解析测试覆盖有效组合、无修饰键和 `Esc`。
- 运行完整单元测试与 Release 构建。
- 安装 `/Applications/Wnip.app` 并启动；验证进程存活、菜单点击出现浮层、默认快捷键出现浮层、设置窗口包含快捷键录制控件。
